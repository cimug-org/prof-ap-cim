== Definition

.Conceptual overview
image::image-2026-06-29-12-20-45-683.png[]

[[dfn-application-profile]](application) profile:: A specification that constrains, extends, combines, or provides guidance for or explanation about the usage of other specifications for a particular application.
[[dfn-cim-profile]]CIM (application) profile:: An application profile of the canonical CIM which conforms to the PROF-AP-CIM specification.

CIM profiles make use of PROF vocabulary to describe profile metadata, and of SHACL to describe the constraints put on
vocabulary used from the CIM, extensions of the CIM or other vocabularies.

=== Resources

PROF-AP-CIM provides resources to help with the creation, validation and use of CIM profiles:

SHACL:: enforces the desired structure of a CIM profile when serialized as RDF
JSON Schema:: helps with authoring profiles in JSON/YAML (including LD) and allows validating
non-RDF JSON/YAML
OWL:: definition of additional PROF-AP-CIM vocabulary not part of PROF or SHACL
JSON-LD context:: syntactic transformations allowing for the mapping between non-LD and LD JSON/YAML and more
comfortable writing of JSON/YAML that is JSON-LD

== Vocabulary

[#shapesGraph]
=== Class: sh:ShapesGraph
[horizontal]
URI:: http://www.w3.org/ns/shacl#ShapesGraph[`sh:ShapesGraph`]
Is defined by:: https://www.w3.org/TR/shacl12-core/[SHACL 1.2 Core]
Subclass of:: `owl:Ontology`

A shapes graph is an RDF graph containing zero or more shapes that is passed into a SHACL validation process so
that a data graph can be validated against the shapes.

== Schema

Each CIM profile MUST have the shape described by the PROF-AP-CIM schema. When representing it in RDF, the SHACL schema
can be used to validate it. For representations in YAML or JSON which are not utilizing JSON-LD, the JSON Schema can be
used.
